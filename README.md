# 클래스로 마켓 | D21 Flask 실습

CSV에 저장된 원데이 클래스 60개를 활용해 만든 Flask 웹서비스입니다.

D20에서는 클래스 목록·상세 페이지·JSON API를 만들었고, D21에서는 **사용자가 직접 후기를 남기고, 저장하고, 찜할 수 있는 기능**을 추가했습니다.

## 1. 프로젝트 소개

### 주요 기능

| 기능 | 설명 |
|---|---|
| 클래스 탐색 | 카테고리별 목록, 검색 조건, 정렬 |
| 클래스 상세 | 클래스 정보 및 후기 조회 |
| 후기 작성 | 닉네임, 별점(1~5), 후기 내용 입력 |
| 후기 저장 | SQLite에 저장하여 서버 재실행 후에도 유지 |
| 입력 검증 | 잘못된 값은 저장하지 않고 오류 안내 |
| 찜하기 | 로그인 없이 클래스 찜·취소 |
| 상태 화면 | 빈 목록, 입력 오류, 저장 성공, 404, 500 |
| JSON API | 클래스 목록·상세·통계 데이터 제공 |

### 사용 기술

## 2. 오늘 배운 핵심 개념

### ① Flask란?

**파이썬으로 웹서비스를 만들 수 있게 도와주는 웹 프레임워크**입니다.

사용자가 페이지를 열거나 버튼을 누르면 Flask가 요청을 받아 처리하고 결과를 돌려줍니다.

- Streamlit: 파이썬으로 화면을 쉽게 만드는 데 적합
- Flask: 웹페이지의 주소, 요청, 서버 동작을 직접 설계하기에 적합

예를 들어 사용자가 후기를 작성하면 Flask가 내용을 받아 검사하고 SQLite에 저장합니다.

### ② GET과 POST — 엽서와 봉투

| 구분 | GET (엽서) | POST (봉투) |
|---|---|---|
| 목적 | 정보 조회 | 정보 제출·변경 |
| 정보 위치 | 주로 URL의 검색 조건 | 요청 본문(body) |
| 예시 | 클래스 목록 보기 | 후기 작성, 찜하기 |
| 새로고침 | 다시 조회 | 중복 제출될 수 있음 |

**GET은 정보를 보여 달라는 요청, POST는 정보를 처리해 달라는 요청**입니다.

POST는 주소창에 내용이 직접 보이지 않지만, POST 자체가 데이터를 암호화하는 것은 아닙니다. 안전한 전송에는 HTTPS가 필요합니다.

### ③ HTTP 상태 코드

서버가 요청을 처리한 결과를 숫자로 알려줍니다.

| 코드 | 의미 | 실제 상황 |
|---|---|---|
| 200 | 정상 처리 | 클래스 페이지 열기 |
| 302 | 다른 주소로 이동 | 후기 저장 후 상세 페이지 이동 |
| 400 | 잘못된 요청 | 별점 6점, 빈 닉네임 |
| 404 | 주소나 대상이 없음 | 존재하지 않는 클래스 |
| 405 | 요청 방식이 틀림 | POST 전용 주소에 GET 요청 |
| 500 | 서버 내부 오류 | 서버 코드 실행 중 오류 |

**404와 405의 차이**

- 404: 주소 자체가 없음
- 405: 주소는 있지만 GET/POST 방식이 맞지 않음

### ④ 데이터베이스와 SQLite

데이터베이스(DB)는 정보를 체계적으로 저장하고 관리하는 공간입니다.

SQLite는 별도 DB 서버 없이 **파일 하나로 데이터를 관리하는 데이터베이스**입니다.

| 용어 | 쉬운 설명 |
|---|---|
| 테이블 | 엑셀처럼 생긴 표 |
| 필드 | 이름, 별점 같은 항목(열) |
| 레코드 | 후기 하나에 해당하는 정보(행) |
| 스키마 | 데이터의 구조와 저장 규칙 |
| SQL | 데이터를 저장·조회·수정·삭제하는 언어 |

이 프로젝트에서는 `reviews.db` 파일에 후기를 저장합니다.

처음에는 파이썬 리스트에 저장했지만, 서버를 종료하면 내용이 사라졌습니다. SQLite로 변경한 뒤에는 로컬 서버를 다시 실행해도 후기가 남습니다.

**CSV와 SQLite 차이**

- CSV: 데이터를 파일에 기록하고 교환하기 편리함
- SQLite: 데이터를 추가·검색·수정하고 규칙에 따라 관리하기 편리함

### ⑤ SQL 주요 명령어

| 명령어 | 의미 |
|---|---|
| CREATE TABLE | 표 만들기 |
| INSERT | 데이터 추가 |
| SELECT | 데이터 조회 |
| UPDATE | 데이터 수정 |
| DELETE | 데이터 삭제 |
| WHERE | 조건에 맞는 데이터 찾기 |

예시:

```sql
-- 후기 추가
INSERT INTO reviews (nickname, rating, content)
VALUES ('민지', 5, '재미있는 수업이었어요');

-- 별점 5점 후기만 조회
SELECT * FROM reviews
WHERE rating = 5;
```

**SQL의 `?` 자리표시자**

사용자 입력값을 SQL 명령에 직접 붙이지 않고 별도로 전달합니다.

```python
conn.execute(
    "INSERT INTO reviews (nickname, rating) VALUES (?, ?)",
    ("민지", 5)
)
```

이렇게 하면 입력한 글자가 SQL 명령으로 해석되는 SQL 인젝션 위험을 줄일 수 있습니다.

### ⑥ 입력값 검증 — 잘못된 데이터 막기

사용자가 입력한 값은 반드시 검사해야 합니다.

이 프로젝트의 후기 입력 규칙은 다음과 같습니다.

| 항목 | 규칙 |
|---|---|
| 닉네임 | 1~20자, 공백만 입력 불가 |
| 별점 | 1~5 사이의 정수 |
| 후기 | 1~200자 |

검증은 두 단계로 이루어집니다.

1. **서버 검증:** 입력값의 길이, 형식, 범위 확인
2. **DB 검증:** `NOT NULL`, `CHECK` 등으로 저장 규칙 확인

잘못된 값이면 저장하지 않고 `400` 오류와 안내 문구를 보여줍니다. 기존에 입력한 내용도 유지하여 다시 작성하지 않도록 합니다.

또한 화면에 사용자 입력값을 표시할 때 Jinja2의 `{{ }}` 자동 이스케이프를 활용하여 HTML이나 스크립트가 그대로 실행되지 않도록 합니다.

### ⑦ PRG — 새로고침 중복 저장 방지

후기를 저장한 직후 새로고침하면 같은 후기가 다시 제출될 수 있습니다.

이를 방지하는 방법이 **PRG(Post → Redirect → Get)** 패턴입니다.

```text
① POST      후기 저장
     ↓
② Redirect  다른 화면으로 이동 (302)
     ↓
③ GET       저장된 후기 목록 조회 (200)
```

이렇게 하면 새로고침해도 후기 목록만 다시 불러옵니다.

함께 사용하는 기능:

- `redirect()`: 저장 후 페이지 이동
- `flash()`: "후기가 저장됐어요" 안내를 한 번만 표시

단, PRG는 빠른 연속 클릭이나 중복 요청 자체를 모두 차단하는 기능은 아닙니다.

### ⑧ 세션과 쿠키 — 로그인 없는 찜하기

로그인하지 않아도 사용자가 찜한 클래스를 기억하기 위해 세션을 사용했습니다.

- **쿠키:** 브라우저에 저장되는 작은 정보
- **세션:** 사용자의 상태를 기억하는 방법
- **Flask 기본 세션:** 쿠키에 데이터를 담고 `SECRET_KEY`로 서명하여 위조를 방지

찜한 클래스 번호를 세션에 저장합니다.

- 찜하기 / 찜 취소 가능
- 찜 목록과 개수 표시
- 브라우저별로 찜 목록이 다름
- 쿠키를 삭제하면 찜 기록이 사라질 수 있음
- 설정한 쿠키 유지 기간은 30일

Flask 기본 세션은 암호화가 아닌 서명 방식이므로 비밀번호 같은 민감한 정보는 저장하지 않습니다.

### ⑨ 환경변수와 .gitignore

비밀 값이나 사용자 데이터가 GitHub에 올라가지 않도록 관리합니다.

| 파일 | 역할 |
|---|---|
| `.env` | SECRET_KEY 등 실제 환경변수 |
| `.env.example` | 환경변수 작성 예시 |
| `.gitignore` | Git에 올리지 않을 파일 지정 |
| `requirements.txt` | 실행에 필요한 파이썬 패키지 목록 |

`.gitignore` 예시:

```gitignore
.env
*.db
__pycache__/
```

`SECRET_KEY`는 코드에 직접 적지 않고 `.env`에 보관합니다.

## 4. 데이터 처리 흐름

사용자가 후기를 작성하면 다음 순서로 처리됩니다.

```text
사용자 후기 입력
       ↓
POST 요청
       ↓
Flask 서버에서 입력값 검사
       ↓
정상 → SQLite 저장
오류 → 400 + 오류 문구
       ↓
저장 성공 시 Redirect (302)
       ↓
GET으로 상세 페이지 다시 조회
       ↓
후기 목록 + 성공 안내 표시
```

**핵심:** 입력 → 검증 → 저장 → 조회 → 화면 표시

## 6. 로컬 실행 방법

### ① 패키지 설치

```bash
pip install -r requirements.txt
```

### ② 환경변수 파일 생성

Windows:

```bash
copy .env.example .env
```

Mac / Linux:

```bash
cp .env.example .env
```

### ③ SECRET_KEY 생성

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

생성된 값을 `.env` 파일에 입력합니다.

```env
SECRET_KEY=생성한_무작위_문자열
FLASK_DEBUG=1
```

### ④ Flask 실행

```bash
flask --app app run --debug
```

브라우저 접속:

http://127.0.0.1:5000

`--debug`는 개발 환경에서만 사용합니다.

## 7. Render 배포 설정

GitHub에 업로드한 코드를 Render에서 실행할 수 있도록 준비했습니다.

| 항목 | 설정 |
|---|---|
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn app:app` |
| Environment | `SECRET_KEY` 설정 |
| Instance Type | Free |

**Gunicorn이란?**

Flask 앱을 배포 서버에서 실행하기 위한 프로그램입니다.

`gunicorn app:app`은 `app.py` 파일 안의 `app` 객체를 실행한다는 의미입니다.

Windows 로컬 개발에서는 Flask 개발 서버를 사용하고, Render의 Linux 환경에서는 Gunicorn을 사용합니다.

## 8. 현재 한계와 개선할 점

| 항목 | 현재 상태 / 개선 방향 |
|---|---|
| 무료 서버 | 사용하지 않으면 잠들어 첫 접속이 느릴 수 있음 |
| 데이터 보관 | Render 무료 인스턴스의 임시 디스크는 재배포·재시작 시 데이터가 사라질 수 있음 |
| 후기 통계 | 새 후기와 CSV의 평점·리뷰 수가 아직 연결되지 않음 |
| 찜 목록 | 브라우저별로 저장되며 다른 기기와 동기화되지 않음 |
| 중복 후기 | 빠른 연속 제출은 중복 저장될 수 있음 |
| CSRF 보안 | 별도 CSRF 토큰 보호가 아직 없음 |

실제 서비스로 확장한다면 영속적인 외부 DB, 로그인, CSRF 보호, 중복 요청 방지 등을 추가할 필요가 있습니다.

### 핵심 배움

D20에서는 데이터를 **보여주는 웹사이트**를 만들었다면, D21에서는 사용자가 직접 데이터를 **입력하고 저장하는 웹서비스**로 확장했습니다.

단순히 기능을 만드는 것뿐 아니라 잘못된 입력, 중복 저장, 오류 화면, 데이터 보관, 배포 환경까지 함께 고려해야 한다는 점을 배웠습니다.
