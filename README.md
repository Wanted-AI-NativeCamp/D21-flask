# 클래스로 마켓 (D21 Flask 실습)

클래스 60개가 들어 있는 CSV로 만든 작은 Flask 웹앱이에요.
D20에서 만든 앱(목록 · 상세 · JSON API)에, D21에서 **값을 남기고 저장하는 기능**과 **배포 준비**를 붙였어요.

## 어떤 실습인가

| 단계 | 한 일 |
|---|---|
| 1. 폼 | 상세 화면(`/class/번호`) 아래에 **수강 후기 남기기** 폼 (닉네임 · 별점 1~5 · 후기 내용) |
| 2. 저장 | 처음엔 파이썬 리스트(메모리)에 저장하다가, **SQLite**(`reviews.db`)로 바꿔서 서버를 껐다 켜도 남게 함 |
| 3. 안내 | 저장하면 같은 화면으로 돌려보내고(PRG), "후기가 저장 됐어요"를 **한 번만** 보여 줌 |
| 4. 세션 | 로그인 없이 쓰는 **찜하기** (`♡ 찜하기` / `♥ 찜 취소`), 찜 목록 화면, 메뉴의 `찜 목록 (개수)` |
| 5. 배포 준비 | `SECRET_KEY`를 `.env`로 옮기기, debug는 내 컴퓨터에서만, 500 에러 화면, `requirements.txt` + `gunicorn` |

## 주소 한눈에 보기

| 주소 | 방식 | 하는 일 |
|---|---|---|
| `/` | GET | 홈 |
| `/classes` | GET | 클래스 목록 (`?category=` `?sort=` `?view=`) |
| `/class/<번호>` | GET | 상세 + 후기 목록 + 후기 폼 |
| `/class/<번호>` | POST | 후기 저장 (틀리면 400, 성공하면 302) |
| `/class/<번호>/wish` | POST | 찜 켜기 / 끄기 |
| `/wishlist` | GET | 내 찜 목록 (여기서도 찜 취소 가능) |
| `/api/classes`, `/api/classes/<번호>`, `/api/stats` | GET | JSON |

## 배운 것

### 1. GET과 POST — 엽서와 봉투
- **GET(엽서)**: 내용이 주소창에 다 보여요. 보기 · 검색처럼 **읽기만** 할 때 써요.
- **POST(봉투)**: 내용이 요청 안쪽에 들어가요. 저장 · 수정 · 삭제처럼 **값을 바꿀 때** 써요.
- 값을 바꾸는 일을 GET으로 만들면 검색 로봇이나 미리보기가 링크를 따라가기만 해도 데이터가 바뀌어요.
- 봉투(POST)는 잠금장치가 아니에요. 진짜로 지켜 주는 건 HTTPS예요.

### 2. 상태 코드

| 코드 | 쉬운 뜻 | 이 앱에서 |
|---|---|---|
| 200 | 잘 받았고, 여기 있어요 | 화면이 정상으로 열릴 때 |
| 302 | 다른 주소로 가세요 | 후기 · 찜 처리 직후 화면으로 돌려보낼 때 |
| 400 | 보낸 값이 틀렸어요 | 빈 닉네임, 별점 6 등 → 저장하지 않고 이유를 보여 줌 |
| 404 | 그런 건 없어요 | 없는 클래스 번호 |
| 405 | 그 방식은 안 받아요 | POST만 받는 주소(`/class/2/wish`)를 주소창으로 열 때 |
| 500 | 서버가 고장 났어요 | 코드에서 에러가 났을 때 → 친절한 화면 (`500.html`) |

405는 "주소는 맞는데 방식이 틀렸어요", 404는 "그 주소가 없어요"예요.
폼의 `method="post"`와 서버의 `methods=["GET", "POST"]`는 짝이 맞아야 해요.

### 2-1. 값 검증은 두 겹으로
- 앱에서 먼저 막아요 (빈 값, 글자 수, 별점 범위).
- DB에서도 한 번 더 막아요 (`NOT NULL`, `CHECK`). 앱 코드에 버그가 있어도 이상한 값이 저장되지 않아요.
- 틀려서 돌아왔을 때 쓴 내용은 지우지 않고 다시 채워 줘요.

### 3. PRG — 새로고침해도 또 저장되지 않게
POST로 저장한 뒤 화면을 바로 보여 주면, 새로고침할 때 같은 POST가 또 가요.
그래서 **POST → redirect(302) → GET** 순서로 해요. 그러면 새로고침은 GET만 다시 보내요.
"저장 됐어요" 안내는 `flash`로 한 번만 보여 줘요 (꺼내면 사라짐).

### 4. SQLite와 `?` 자리표시자
- DB 전체가 파일 하나(`reviews.db`)예요. 표를 만들고(`CREATE TABLE`), 넣고(`INSERT`), 꺼내요(`SELECT`).
- 표 설계: `id`, `class_id`, `nickname`, `rating`, `content`, `created_at` (전부 꼭 있어야 함)
- 사용자 값은 **절대 SQL 문장에 이어 붙이지 않고 `?` 자리에** 넘겨요. 그래야 값이 명령이 되지 않아요 (SQL 인젝션 방어). `x'); DROP TABLE reviews;--`를 넣어도 그냥 글자로 저장돼요.
- 템플릿에서는 값을 `{{ }}`로만 보여 줘요. `<script>`를 넣어도 글자로 보여요(자동 이스케이프).

### 5. 세션과 쿠키
- **쿠키**: 손님 브라우저에 든 쪽지예요. 내용이 다 보이고 고칠 수도 있어요.
- **세션**: 원래는 서버가 내용을 보관하고, 손님에게는 번호표만 줘요.
- **Flask 세션**은 내용을 쿠키에 담되 `SECRET_KEY`로 **도장(서명)**을 찍어요. 읽을 수는 있지만 고치면 도장이 안 맞아 무효가 돼요. 그래서 비밀번호 같은 건 넣지 않아요.
- 찜 목록은 DB 없이 세션에 번호만 담아요. 브라우저를 닫아도 30일 남게 했어요. 로그인이 없으니 쿠키가 "나"를 알아보는 유일한 방법이에요.
- 열쇠(`SECRET_KEY`)가 바뀌면 모든 손님의 찜과 안내가 한 번에 사라져요.

### 6. 비밀 값과 `.gitignore`
- `SECRET_KEY`는 코드에 쓰지 않고 `.env`에 둬요. `python-dotenv`가 읽어요. 없으면 앱이 켜지다가 이유를 알려 주며 멈춰요.
- `.env.example`에는 칸 이름과 설명만 있고 값은 없어요. 새로 받은 사람이 복사해서 채워요.
- `.env`, `*.db`, `__pycache__/`는 깃에 올리지 않아요 (비밀 · 손님 데이터 · 임시 파일).
- 깃에 안 올릴 것은 `git status`로 올리기 전에 꼭 확인해요.

### 7. 배포를 위한 준비
- **debug는 내 컴퓨터에서만**: `.env`의 `FLASK_DEBUG=1`일 때만 켜져요. 서버에서 켜 두면 에러 화면에서 서버 코드가 실행될 수 있어 위험해요.
- **500 에러 화면**: 손님에게는 "문제가 생겼어요"만 보여 주고, 에러 내용은 서버 로그에만 남겨요. `/api`는 JSON으로 답해요.
- **`requirements.txt`**: 서버가 필요한 패키지를 그대로 설치하도록 버전을 고정해요.
- **`gunicorn`**: 서버에서 앱을 켜는 프로그램이에요 (`gunicorn app:app` = 파일 이름:변수 이름).
- 새 서버에는 DB 파일이 없어서, 연결할 때 "표가 없으면 만든다"를 실행해요.

## 내 컴퓨터에서 켜는 법

```bash
# 1. 패키지 설치
pip install -r requirements.txt

# 2. .env 만들기 (Windows는 copy, Mac/Linux는 cp)
copy .env.example .env

# 3. .env를 열어서 채우기
#    SECRET_KEY=  ← 아래 명령으로 만든 글자를 붙여 넣기
#    FLASK_DEBUG=1
python -c "import secrets; print(secrets.token_hex(32))"

# 4. 켜기 → http://127.0.0.1:5000
flask --app app run --debug
```

> gunicorn은 Windows에서 실행되지 않아요. 내 컴퓨터에서는 위처럼 `flask`로 켜고, gunicorn은 서버(리눅스)에서만 써요.

## 배포 (Render)

| 칸 | 값 |
|---|---|
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn app:app` |
| Environment | `SECRET_KEY` = 새로 만든 긴 무작위 글자 (`FLASK_DEBUG`는 적지 않기) |
| Instance Type | Free |

## 폴더 구조

```
D21-Flask/
├─ app.py              주소와 화면 연결, 후기 · 찜 처리, 에러 화면
├─ data.py             CSV 읽기, 거르기 · 정렬 · 통계
├─ db.py               SQLite: 연결 · 표 만들기 · 후기 넣기 · 꺼내기
├─ data/classes.csv    클래스 60개
├─ templates/          base · 목록 · 상세 · 찜 목록 · 404 · 500 등
├─ static/             style.css, 이미지
├─ requirements.txt
├─ .env.example        채워야 할 칸 안내 (값 없음)
└─ .gitignore          .env · *.db · __pycache__ 등
```

## 한계와 다음에 할 것

- **무료 서버는 15분 쉬면 잠들어요.** 첫 접속은 1분쯤 걸려요.
- **무료 서버의 디스크는 임시예요.** 재배포나 재시작 때 `reviews.db`가 지워질 수 있어요. 진짜 서비스는 외부 DB가 필요해요.
- 카드의 평점과 리뷰 수는 CSV 값 그대로예요. 새로 남긴 후기와 아직 연결되지 않았어요.
- 찜은 브라우저마다 따로예요. 쿠키를 지우거나 다른 기기로 오면 비어 있어요.
- "후기 남기기"를 빠르게 두 번 누르면 같은 후기가 두 개 저장될 수 있어요.
- 폼에 CSRF 토큰이 없어요. 남이 내 브라우저로 POST를 보내는 공격을 아직 완전히 막지 못해요.
